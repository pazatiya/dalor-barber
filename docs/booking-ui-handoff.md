# DALOR — ממשק קביעת תורים

עודכן ב־9 באוקטובר 2026 בפרויקט הקיים `yair_barber_booking`.

## גבולות השינוי

השינויים של סבב העיצוב הם ב־`public/index.html` ובקובץ החדש `public/booking-ui.css` בלבד, מלבד מסמך זה. לפני העבודה היו שינויים קיימים בשרת, במנהל ובקבצי הפרויקט. לא הוחלפו או בוטלו. השוואת SHA של `server.js`, כל קובצי `lib/*.js` וקובצי `public/admin*` מול תחילת סבב העיצוב לא הראתה שינויים במהלך העבודה. הלוגו המקורי `/logo.jpg` נשאר ללא שינוי ומוצג עם object-fit:contain.

## המסכים והרכיבים

- פתיחה: הלוגו בשלמותו, הבית לגבר, הכותרת והטקסט שנדרשו וכפתור קביעת תור.
- מספר אנשים: כרטיסים ממוספרים 1–4 בהתאם למגבלת השרת, סימון זהב וכפתור המשך.
- שירותים: הקטלוג הפעיל מהשרת, מחיר מאושר או הודעת תיאום מחיר, חלוקה ללקוח 1–4.
- סוג תספורת: רק לאנשים ששירותם כולל תספורת; קודם לתוספות.
- תוספות: ריבוי בחירות, ללא תוספות מבטל בחירות קיימות ואפשר להמשיך ללא בחירה.
- קבוצה: ברצף, במקביל או הזמן הקרוב, רק ליותר מאדם אחד.
- פרטים: שם, טלפון, לקוח חדש/חוזר והערות אופציונליות; נשמרים גם בחזרה לפני שליחת הטופס.
- תזכורות: שלב נפרד עם כן/לא ללא הסכמה ראשונית.
- תאריך ושעה: בדיקת זמינות מהשרת לפי השירותים והקבוצה; ימים שלא נבדקו, סגורים או מלאים אינם פעילים. כפתורי שעות, טעינה, ניסיון חוזר וחיפוש היום הבא עם זמינות. בחירת שעה דורשת המשך מפורש.
- סיכום: הצעת מחיר מהשרת, הזמן המשוריין, שירותים ותוספות לכל לקוח, פרטים, הערות ותזכורת. האישור דורש הצעת מחיר תקינה והסכמה למדיניות, ומוגן משליחה כפולה.
- הצלחה: מופיעה אחרי תשובת הזמנה מהשרת בלבד. pending מוצג כבקשה שהתקבלה ועדיין ממתינה לאישור. פרטי הזמנה וקישור ניהול אמיתי.
- ניהול ואזור אישי: משתמשים בחיבורים הקיימים וקיבלו את העיצוב המשותף של ממשק הלקוח.

RTL, labels, הודעות role=alert/status, פוקוס מקלדת, aria-pressed לבחירות, התקדמות נגישה, חסימת פוקוס למסך מוסתר, תמיכה בזום וב־Reduced Motion, כפתור תחתון במובייל ו־Safe Area.

## תאימות לשרת

נעשה שימוש ב־`/api/v2/catalog`, `/calendar`, `/availability`, `/quote`, `/bookings`, `/me` ובנתיבי ניהול וביטול לפי token. מבנה payload ההזמנה נשמר. אין בחירת ספר ואין שינוי במנוע שיבוץ, בסכמת הנתונים או בתמחור.

בדיקת הזמינות לחודש המוצג נעשית במקבצים של עד 3 בקשות, ונשמרת במטמון לפי בחירות. בחירת יום בודקת מחדש את השעות; שמירת ההזמנה נשארת ההכרעה הסופית. מגבלת השרת הקיימת היא 60 בקשות בדקה; שינויים רבים בבחירות או מעבר חוזר בין חודשים יכולים להפעיל אותה ומוצגת אפשרות ניסיון חוזר. API מרוכז לזמינות ימים יוכל לצמצם את מספר הבקשות בעתיד.

## בדיקות שבוצעו

- `npm test`: כל 52 הבדיקות הקיימות עברו.
- Chromium מקומי ברוחבים 360, 390, 768 ו־1440: מסכי פתיחה, אנשים ובחירות; ללא גלילה אופקית וללא שגיאות JavaScript. נבדקו תמונות המסכים.
- מסלול קבוצתי מלא ברוחב 390 מול API אמיתי ומסד בזיכרון: שני שירותים שונים, תספורת, תוספות, מקביל, שמירת פרטים בחזרה, הסכמה מפורשת, הצעת מחיר, POST 201, קישור ניהול וביטול אמיתי.
- בדיקות נפרדות עם הדמיית תשובות רשת מקומית בלבד: 409 ושיבה לשעות, יום מלא והיום הבא, 503 וניסיון חוזר, pending ללא הודעת אישור סופי. נבדקה שמירת השעה לאחר חזרה מהסיכום.
- מצבי טעינה ראשונית, שגיאה וניסיון חוזר נבדקו בהדמיית תעבורה מקומית.
- לא בוצעה בדיקה במכשירי iPhone/Android פיזיים או ב־Safari. לא בוצעה פריסה לפרודקשן.

## תלות שנותרה בצד Claude / אישור העסק

הקטלוג הציבורי אינו מחזיר `durationMin` ו־`durationConfirmed`. הכרטיסים כבר מוכנים להציג משך רק אם יוחזר אישור מפורש; כרגע אין בהם מספרים משוערים. הסיכום מציג את חלון הזמן שהשרת משבץ, שאינו הבטחה למשך טיפול מאושר. אישור משכים ומחירים חסרים נשאר בניהול העסק.

העדפת WhatsApp נשלחת ונשמרת בחוזה הקיים. מסירת הודעות בפועל תלויה בספק WhatsApp, תבניות ו־worker/cron של Claude; מסירה חיצונית לא נבדקה בסבב UI זה.

הפריסה והבדיקה מול מסד הייצור עדיין נדרשות. שרת התצוגה המקומי שהופעל לבדיקה משתמש במסד בזיכרון; הזמנותיו אינן הזמנות עסקיות אמיתיות.
